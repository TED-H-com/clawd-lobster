A memory and a reviewer for Claude Code.

給 Claude Code 一份記憶，
再加一位審查者。

Each workspace gets its own SQLite memory over MCP. Before any code is written, an Architect session drafts a spec and a separate Reviewer session challenges it. Scheduled jobs carry what was learned to your other machines through git.

每個工作區都有自己的 SQLite 記憶，透過 MCP 存取。動手寫程式之前，Architect session 先起草規格，再由另一個獨立的 Reviewer session 挑毛病。排程工作再透過 git，把累積的知識帶到你的其他機器。

The problem問題在哪裡

Context gets lost between sessions and machines.

換了對話、換了機器，
脈絡就斷了。

Decisions, open TODOs, and lessons from failed attempts end up scattered across chat logs and one long CLAUDE.md, and each machine keeps its own copy. A spec written and approved by the same session carries its gaps straight into the code. Clawd-Lobster gives each workspace a structured memory, syncs it through git, and puts a separate reviewer between the spec and the build.

決策、還沒做完的 TODO、失敗過的嘗試，最後散落在對話紀錄和一份越寫越長的 CLAUDE.md 裡，每台機器還各有一份。由同一個 session 撰寫又自己核准的規格，會把漏洞原封不動帶進程式碼。Clawd-Lobster 讓每個工作區有結構化的記憶，透過 git 同步，並在規格與實作之間安排一位獨立的審查者。

The Reviewer never sees the Architect's instructions. It gets the spec files and read-only tools, and its only job is to find what is wrong.
Reviewer 看不到 Architect 的指示，
只有規格和唯讀工具，
它的工作就是找出問題。
How it works運作方式

Set up once. Then every project runs the same loop.

設定一次，
之後照流程走。

The browser and the terminal drive the same engine, and every step leaves files in the workspace that you can open and read.

瀏覽器和終端機驅動的是同一套引擎，每一步都會在工作區留下檔案，隨時可以打開來看。

01

Onboard

完成設定

clawd-lobster serve opens a setup wizard on localhost:3333: language, Claude sign-in, a private GitHub Hub, the workspace root, then each required skill. The install scripts cover similar ground from a terminal.

clawd-lobster serve 會在 localhost:3333 打開設定精靈：語言、Claude 登入、私人的 GitHub Hub、工作區根目錄，接著逐一設定必要的 skill。安裝腳本則在終端機完成類似的設定。

02

Describe the project

描述專案

In the browser, a discovery chat asks follow-up questions until it has enough to start. In the terminal you type the description and press Enter twice.

在瀏覽器裡，探索對話會一直追問，直到資訊足夠才開始。在終端機則是直接輸入描述，按兩次 Enter 結束。

03

Spec, review, build

規格、審查、實作

The Architect writes OpenSpec files with SHALL/MUST requirements and Gherkin scenarios. The Reviewer challenges them for up to five rounds, the Coder builds from tasks.md, and the Tester checks each requirement. Terminal mode asks before building.

Architect 寫出 OpenSpec 檔案，需求用 SHALL/MUST 描述並附上 Gherkin 情境。Reviewer 最多挑戰五輪，接著 Coder 依 tasks.md 實作，Tester 逐條檢查需求。終端機模式在開始實作前會先問你。

04

Remember and sync

記住並同步

Decisions, TODOs, and an action log go into a SQLite file in each workspace. With the install scripts, a job every 30 minutes pulls, commits, and pushes the repositories under the workspace root.

決策、TODO 與操作紀錄寫進各工作區自己的 SQLite 檔。用安裝腳本安裝的話，排程工作每 30 分鐘會對工作區根目錄底下的 repo 執行 pull、commit 與 push。

Nobody reviews their own spec

自己寫的，不自己審

The Reviewer is a separate session. It sees the spec files, not the Architect's instructions.

Reviewer 是另一個 session，只看得到規格檔，看不到 Architect 收到的指示。

What you get你會得到什麼

Plain parts around Claude Code.

Claude Code 不動，
只在外圍加零件。

Each piece is a Python module, a script, or a folder of Markdown and JSON. Claude Code itself is never patched.

每個零件都是一個 Python 模組、一支腳本，或是一個裝著 Markdown 與 JSON 的資料夾。Claude Code 本身完全不動。

01

A four-role Spec Squad

四個角色的 Spec Squad

Architect, Reviewer, Coder, and Tester each run as fresh Claude Agent SDK sessions with their own prompts and tool lists. The Reviewer can only read, and only the Coder and Tester can run shell commands.

Architect、Reviewer、Coder、Tester 每一輪都在全新的 Claude Agent SDK session 裡執行，各有自己的 prompt 與可用工具。Reviewer 只能讀檔，只有 Coder 和 Tester 能執行 shell 指令。

clawd_lobster/squad.py
02

Memory over MCP

MCP 記憶伺服器

A FastMCP server with 27 tools for decisions, knowledge, TODOs, learned skills, and an audit trail, stored in SQLite per workspace. Salience rises when an item is used and decays when it is not, and search ranks by it. It grew out of mcp-memory-server.

以 FastMCP 寫成，提供 27 個工具，記錄決策、知識、TODO、學到的 skill 與稽核軌跡，每個工作區各存一份 SQLite。項目被用到時 salience 上升，閒置時衰減，搜尋結果依此排序。前身是 mcp-memory-server。

skills/memory-server/
03

A local dashboard

本機儀表板

clawd-lobster serve runs a standard-library HTTP server on 127.0.0.1 with pages for setup, workspaces, skills, credentials, and a live Squad view. The browser and a Claude Code session share one controller lease, so only one of them drives setup at a time. Every POST needs the token from that run, a local Host header, and a matching Origin.

clawd-lobster serve 用 Python 標準函式庫在 127.0.0.1 啟動 HTTP 伺服器，提供設定、工作區、skill、憑證與即時 Squad 畫面。瀏覽器和 Claude Code session 共用一份控制權租約，同一時間只有一方能操作設定。每個 POST 都要帶這次啟動產生的 token，Host 必須是本機，Origin 也要相符。

clawd_lobster/server.py
04

Skills with manifests

附資訊清單的 skill

Eleven skills in four kinds: MCP server, prompt pattern, cron job, and poller. Each skill.json declares credentials, a health check, and dependencies, plus setup steps for the six required ones; prompt patterns ship a SKILL.md for Claude to follow.

11 個 skill 分成四類：MCP 伺服器、prompt 模式、cron 排程與輪詢器。每個 skill.json 都寫明所需憑證、健康檢查與相依項目，六個必要的 skill 另外寫好設定步驟；prompt 模式則附一份 SKILL.md 讓 Claude 照著做。

skills/*/skill.json
05

A Hub across machines

跨機器的 Hub

Setup creates or joins a private GitHub repository as the Hub. The install scripts also schedule a job that pulls, commits, and pushes every repository under the workspace root every 30 minutes, so the next machine sees the same knowledge files.

設定流程會建立或加入一個私人 GitHub repo 當作 Hub。安裝腳本另外排了一個工作，每 30 分鐘對工作區根目錄底下的每個 repo 執行 pull、commit 與 push，另一台機器就能看到同樣的知識檔案。

scripts/sync-all.sh
06

Review on a timer

定時回顧

Every two hours, evolve-tick asks Claude to look over finished TODOs and recent actions, stores reusable patterns as learned skills, decays stale salience, and lints the knowledge wiki. Improvement ideas are committed as proposal files for a person to review.

evolve-tick 每兩小時請 Claude 檢視完成的 TODO 與最近的操作，把可重複使用的做法存成 learned skill，讓久未使用的項目 salience 衰減，並檢查知識 wiki。改進想法會寫成提案檔 commit 進去，等人審查。

scripts/evolve-tick.py

Four kinds of skill

skill 分成四種

Every skill has a skill.json that names its kind, credentials, health check, and dependencies.

每個 skill 都有一份 skill.json，寫明類型、憑證、健康檢查和相依項目。

One driver at a time

一次只能一邊改設定

Both the browser and Claude Code can change setup, so each has to hold the same lease first.

瀏覽器和 Claude Code 都能改設定，所以要先拿到同一份租約。

Look back every two hours

每兩小時回頭看一次

What finished work teaches is kept, and ideas for improvement are written down for a person.

做完的事，學到的要留下來，想改進的先寫下來等人看。

Design decisions設計取捨

Why it is shaped
this way.

為什麼長這個樣子。

01

Wrap Claude Code, do not replace it

包住 Claude Code，而不是取代它

Agent loops, model calls, and tool use stay inside Claude Code and the Agent SDK. This repository only adds memory, specs, scheduling, and setup around them, so most Claude Code updates need no changes here.

agent 迴圈、模型呼叫與工具使用都留在 Claude Code 和 Agent SDK 裡。這個 repo 只在外圍加上記憶、規格、排程與設定，所以 Claude Code 大部分的更新都不需要這裡跟著改。

02

Separate sessions for writing and reviewing

撰寫和審查分成不同的 session

The Reviewer gets its own prompt and read-only tools and never sees the Architect's instructions. The cost is time and tokens: every review round is a full session, which is why the loop stops after five rounds.

Reviewer 有自己的 prompt 和唯讀工具，看不到 Architect 收到的指示。代價是時間與 token：每一輪審查都是一個完整的 session，所以迴圈最多只跑五輪。

03

Git as the sync protocol

用 git 當同步協定

Machines share knowledge through a private GitHub repository instead of a shared database. No server is needed, but sync means scheduled commits and pushes, and a merge conflict stalls that repository until someone resolves it.

機器之間透過私人 GitHub repo 分享知識，而不是共用資料庫。不需要另外架伺服器，代價是排程會自動 commit 與 push；遇到合併衝突時，那個 repo 的同步就會卡住，直到有人處理。

04

SQLite first, Oracle optional

先用 SQLite，Oracle 可選

Every workspace works with a local SQLite file and plain text search. Vector search, cross-machine recall, and the Vault turn on only when you connect an Oracle database and an embedding endpoint.

每個工作區只要本機的 SQLite 檔案與一般文字搜尋就能運作。向量搜尋、跨機器回想與 Vault，要接上 Oracle 資料庫和 embedding 端點才會啟用。

Sync through git

每台機器靠 git 同步

No server is needed. The cost: a merge conflict stops that repo until a person fixes it.

不用另外架伺服器。代價是遇到合併衝突時，那個 repo 會停下來等人處理。

Where it stands.

目前的樣子。

Experimental. 136 commits between April 1 and April 9, 2026, then October 2026 fixes: the local web server was locked down, scheduling was fixed, host names are no longer written out, and the Linux sync no longer stops when a file pattern matches nothing. No tagged releases; the changelog now covers 0.6.0.

實驗性質。2026 年 4 月 1 日到 9 日之間有 136 個 commit，2026 年 10 月又做了修正：鎖住本機網頁伺服器、修好排程、不再寫入主機名稱，Linux 的同步也不會再因為某種檔案類型比對不到就中止。沒有正式的 release；CHANGELOG 已補上 0.6.0。

Limits and not yet

限制與尚未完成

  • No feature work since April 9, 2026, and not checked against later Claude Code or Agent SDK releases
  • 2026 年 4 月 9 日之後沒有新功能，也沒有針對之後的 Claude Code 或 Agent SDK 版本驗證過
  • If the Reviewer has not approved after five rounds, the spec still counts as approved, marked as forced by the round limit, and the web flow goes on to build
  • 審查五輪後若 Reviewer 仍未核准，規格還是會被當成已核准，只是標記為回合上限強制通過，網頁流程也會直接進入實作
  • The 30-minute sync, which only the install scripts schedule, commits and pushes each git repository under the workspace root when the index has changes. It stages tracked updates and new Markdown, JSON, YAML, HTML, and script files. Other new files stay untracked, and ignored files stay ignored. Keep anything you do not want pushed outside that folder
  • 每 30 分鐘的同步（只有安裝腳本會排程）會在索引裡有變更時，對工作區根目錄底下的每個 git repo 自動 commit 並 push。已追蹤檔案的更新，以及新的 Markdown、JSON、YAML、HTML 與腳本檔會被加進去；其他新檔案維持未追蹤，被忽略的檔案也不會加進去。不想被推上去的東西請放在這個資料夾以外

  • connect-odoo 的輪詢器還不能排程，設定時會回報找不到進入點

  • Heartbeat 只用程式名稱判斷 session 是否還在執行，重新開啟時也只是執行單純的 claude --resume，會開出 session 選單，而不是接回特定的 session
  • Spec Squad needs the [agent] extra; vector search and the Vault need an Oracle database; the memory server needs Python 3.11 or newer
  • Spec Squad 需要 [agent] 選用相依套件；向量搜尋與 Vault 需要 Oracle 資料庫；記憶伺服器需要 Python 3.11 以上
